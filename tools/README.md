# Tools

| Path | What it does |
|---|---|
| `card-bills/` | Links credit-card bill lines in bank accounts to the right card account (see its README). |
| `reminders/check-merchant.sh` | One-time check, run from cron, that a merchant stopped charging (e.g. after cancelling a subscription). Runs as the bot user. Writes the result to `/var/log/finance-reminders.log` (owned by the bot user) and to the assistant's handover file. `cron.example` shows the schedule format. |
| `telegram/start-bot.sh` | Starts the Claude Code Telegram channel session in a detached tmux session, as the unprivileged bot user (see design.md, step 7). `bot-settings.json` enables the Telegram plugin only for that session, so other Claude sessions don't take over the bot. `cron-reboot.example` starts it after a reboot (start-bot.sh sets the PATH: the plugin is a [Bun](https://bun.sh) program). |
| `telegram/mcp.example.json` | Optional MCP servers for the bot, read from `~/.config/finance/mcp.json`: Google Drive and Sheets ([workspace-mcp](https://github.com/taylorwilsdon/google_workspace_mcp), signed in once with an OAuth client; sharing and sign-in tools disabled) and WhatsApp through [wa-gateway](https://github.com/kolmanv/wa-gateway). Allow the tools (`mcp__google__...`, `mcp__wa__...`) in the bot's settings. The Google login is readable by the bot user. |
| `telegram/wa-proxy.nginx.example` | Root-only nginx proxy on 127.0.0.1 that adds the Cloudflare Access service token to wa-gateway requests, so the bot uses WhatsApp but can't read or leak the token. |
| `refresh/` | On-demand imports for the bot. The bot runs `finance-refresh-request <bank>...` (installed in /usr/local/bin), which only drops a request file; root's `finance-refresh tick` (every minute, in /usr/local/sbin) runs `run.sh` for just those banks as soon as the caps allow (each bank at most once per `GAP_MINUTES`, `EXTRA_PER_DAY` extra runs; requests wait, they are never refused), then types `[refresh done ...]` into the bot session. The bot never sees the bank logins: the limited config reaches moneyman through root's environment. Setup: `/var/lib/finance-refresh` (root:finbot 0750) with `requests/` (root:finbot 1730), `cron.example`, `finance-refresh.default.example`, and allow `Bash(finance-refresh-request *)` in the bot's settings. |
| `schedule/` | The bot's durable schedule (design.md, step 8): `finance-import-summary` (per-bank import health after each run), `finance-bot-say` (types a message into the bot session), `finance-bot-due` (dated one-off reminders), `finance-bot-watchdog` (Telegram alert without Claude if no digest by 09:30), `cron.example`, `finance-watchdog.conf.example`. |

Deployment pieces are in `../deploy/`: `run.sh` (import: moneyman -> Actual, then card-bills, then prune old moneyman output; all banks, or only the companyIds given), `cron-moneyman` and `logrotate-moneyman`.
